test2_【問題60：マルチアカウント移行のガバナンス】問題文:企業がAWSへ移行し、開発・ステージング・本番・共有ネットワークの別アカウントを作成します。
MFA必須で集中管理されたアクセスが必要で、ネットワークはプライベートに保ちたいです。
どの3つの手順を選ぶべきですか。選択肢:
A:_AWS_Control_Towerでランディングゾーンをデプロイする
B:_IAMユーザーとAmazon_Cognitoでアカウント間アクセスを管理する
C:_AWS_IAM_Identity_Centerを有効化し、適切な許可セットを作成する
D:_AWS_Control_Towerでアカウント間ルーティングを管理する
E:_共有ネットワークアカウントでTransit_Gatewayを作成し、各アカウントのVPCアタッチメントとルートテーブルを設定する

【正解】A、C、E

【解説】
この問題では、次の3つの要件をそれぞれ適切なAWSサービスで満たす必要があります。

1. 複数のAWSアカウントを統制された方法で作成・管理する
2. MFAを使用したアクセスを一元管理する
3. 各アカウントのネットワークをインターネットに公開せず、プライベートに接続する

まず、AWS Control Towerでランディングゾーンをデプロイします。
Control TowerはAWS Organizationsを基盤として、複数アカウント環境のセットアップ、組織単位（OU）の管理、
アカウント作成、統制ルールの適用を支援します。開発、ステージング、本番、共有ネットワークなどを
別アカウントに分離しながら、一貫したガバナンスを適用できます。

次に、AWS IAM Identity Centerを有効化します。IAM Identity Centerでは、利用者とグループを一元管理し、
許可セットを使って各AWSアカウントに必要な権限を割り当てられます。外部のIDプロバイダーとの連携や
MFAの適用にも対応しており、アカウントごとにIAMユーザーを作る方式より安全で管理しやすくなります。

ネットワークにはAWS Transit Gatewayを使用します。共有ネットワークアカウントにTransit Gatewayを配置し、
各アカウントのVPCをアタッチしてルートテーブルを設定すると、ハブアンドスポーク型のプライベート接続を構成できます。
多数のVPCを個別のVPCピアリングで接続する場合に比べ、接続とルーティングを集中管理しやすくなります。

したがって、マルチアカウントのガバナンスにA、アクセスの集中管理にC、プライベートネットワーク接続にEを選択します。

【各選択肢の判断】
A: 正解。AWS Control Towerにより、統制されたマルチアカウント環境であるランディングゾーンを構築できます。

B: 不正解。アカウントごとのIAMユーザーは認証情報と権限の管理が分散します。
また、Amazon Cognitoは主にWebアプリケーションやモバイルアプリケーションの利用者認証に使うサービスであり、
従業員による複数AWSアカウントへのアクセスを集中管理するための最適なサービスではありません。

C: 正解。IAM Identity Centerと許可セットを使用すると、複数のAWSアカウントへのアクセスと権限を一元管理でき、
MFAも適用できます。

D: 不正解。AWS Control Towerはアカウントのガバナンスを管理するサービスであり、
VPC間のパケット転送やルーティングを担うサービスではありません。アカウント間のネットワーク接続には
Transit Gatewayなどを使用します。

E: 正解。Transit Gatewayに各VPCを接続することで、共有ネットワークアカウントを中心としたプライベートな
ネットワーク接続とルーティングの集中管理を実現できます。

【覚え方】
マルチアカウント環境では、目的ごとにサービスを切り分けます。
アカウントの統制 → AWS Control Tower
人と権限の集中管理 → AWS IAM Identity Center
VPC間のプライベート接続 → AWS Transit Gateway
