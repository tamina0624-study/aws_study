全体的な説明

前提知識
SageMaker Model Monitorのデータ品質モニタリングについて
本番環境にデプロイされたモデルへ送られる入力データの統計的特性を監視する機能です。トレーニングデータから統計と制約のベースラインを生成し、本番データをベースラインと比較してドリフトを検出します。ベースラインジョブはDeequ（Apache Sparkベースのオープンソースライブラリ）を使って各特徴量の統計を計算します。emit_metricsオプションを有効にすると、特徴量ごとの統計メトリクスがCloudWatchへ自動で出力され、スケジュール実行によって定期的に監視できます。
SageMaker Model Monitorのモデル品質モニタリングについて
モデルの予測品質（正解率、適合率、再現率、F1スコア、AUCなど）を監視する機能です。予測結果と正解ラベルを照合して性能の劣化を検出します。入力データの分布変化ではなく、モデルの出力品質に焦点を当てています。
AWS CloudTrailについて
AWS APIの呼び出し履歴を記録し、誰がいつどの操作を行ったかを監査するためのサービスです。APIの実行記録を残すものであり、推論時に送られる入力データの統計的分布の変化を検出する機能はありません。
SageMakerエンドポイントのCloudWatch標準メトリクスについて
SageMakerはエンドポイントごとにInvocations、InvocationsPerInstance、ModelLatency、OverheadLatencyといったメトリクスをCloudWatchへ発行します。呼び出し件数や応答時間の傾向、インスタンスの負荷を把握してオートスケーリングの判断に使う指標であり、リクエストに含まれる特徴量の統計量は含まれません。入力分布の変化を捉えるには、Model Monitorが算出してCloudWatchへ送るデータ品質のメトリクスを別途用意する必要があります。
図による解説



データ品質モニタリングの構成は、推論エンドポイント・ベースライン・監視・通知の4つの層で成り立ちます。エンドポイントが受け取った入力データはData CaptureでS3に保存され、トレーニングデータから作成した統計ベースラインと突き合わせてModel Monitorが比較します。制約ファイルでemit_metricsを有効にしておくと、各特徴量の統計メトリクスがCloudWatchへ流れ、閾値超過をCloudWatchアラームが検知して通知します。重要なのは、比較の対象が「モデルの予測精度」ではなく「入力データの統計的特性」である点です。この軸を誤ってモデル品質モニタリングやAPI監査を選ぶと、本番で進行するデータドリフトを検知できず、劣化に気付かないまま運用を続けてしまいます。



上段のベースライン分布（トレーニング時の青）に対し、下段の本番データの分布（赤）は平均値が右へ移動し、ばらつきも大きくなっています。トレーニング時の分布と本番の分布が乖離すると、モデルが前提とした入力の傾向が崩れ、予測精度が静かに劣化します。Model Monitorのデータ品質モニタリングは、この「分布のずれ」を特徴量ごとの統計メトリクスとして定量化し、閾値を超えた変化を自動で検知します。ドリフトは徐々に進行するため、人手でログを眺める方法では発見が遅れがちです。定期実行される監視ジョブとCloudWatchアラームを組み合わせると、劣化の兆候を早期に捉えられます。



Model Monitorが監視する指標は2種類あります。上段のデータ品質モニタリングは、平均値・標準偏差・欠損率・最小値・最大値など「入力データの統計的特性」をベースラインと比較します。下段のモデル品質モニタリングは、正解率・F1スコア・AUCなど「予測の正確さ」を監視します。要件が「入力特徴量の分布変化の検知」である以上、見るべきは上段のデータ品質です。モデル品質は予測と正解ラベルの照合を要し、入力の分布がずれていても正解ラベルが無ければ検知できません。2つの監視を混同してモデル品質だけを導入すると、ドリフトによる劣化を見逃します。入力分布の変化を見るならデータ品質モニタリングを選びます。
解くための考え方
この問題の要件は3つに分解できます。監視の対象が「入力特徴量の分布」であること、検知が自動であること、そして運用負荷が最小限であることです。3つのうち最初の1つが選択肢を絞る鍵になります。監視できる対象がインフラの指標なのか、予測の正しさなのか、入力データそのものの統計量なのかを見分ければ、残る選択肢は1つになります。
CloudWatchの標準メトリクスは、Invocationsのような呼び出し回数やModelLatencyのような応答時間を表す指標で、リクエストの中身までは踏み込みません。しかも分布の変化は担当者が人手でログを分析して判断する構成になっており、自動検知と運用負荷最小という2つの条件も同時に外れます。CloudTrailはAPIの呼び出し履歴を監査するサービスで、記録されるのは操作の事実であり、特徴量の統計量を算出する仕組みはありません。
残る2つはいずれもModel Monitorですが、監視の種類が異なります。モデル品質モニタリングは予測結果と正解ラベルを突き合わせ、正解率やF1スコア、AUCの劣化を検出する機能です。評価しているのはモデルの出力の正しさであり、正解ラベルが手に入るまで判定できないという制約も伴うため、入力分布のずれをいち早く捉える用途には合いません。
これに対してデータ品質モニタリングは、トレーニングデータから生成した統計と制約のベースラインに対し、本番へ送られた入力データの平均値・標準偏差・欠損率などを比較してドリフトを検出します。制約ファイルでemit_metricsを有効にすると特徴量ごとの統計メトリクスがCloudWatchへ出力され、CloudWatchアラームで通知まで自動化できます。監視ジョブはスケジュール実行されるため、運用負荷を抑えたまま継続的に監視できます。「入力分布の変化を見るならデータ品質、予測の正しさを見るならモデル品質」という切り分けが判断の軸になります。

前提知識
画像分類について
画像分類は、画像全体にラベルを付けるタスクです。たとえば「この画像はボトルの画像です」というように、画像がどのカテゴリに属するかを予測します。Amazon SageMakerのイメージ分類アルゴリズムは、畳み込みニューラルネットワーク（ResNet）を用いた教師あり学習アルゴリズムで、マルチラベル分類にも対応し、1枚の画像に複数のラベルを出力できます。学習用の画像が十分に集まらない場合は、ゼロから学習する代わりに転移学習で学習することもできます。ただしいずれの場合も出力はラベルとその確信度だけで、物体が画像のどこにあるかという位置情報は返しません。
オブジェクト検出について
オブジェクト検出は、画像内の複数の物体を同時に識別し、それぞれの位置をバウンディングボックス（左上の座標、幅、高さ）として返すアルゴリズムです。1枚の画像から複数の物体を検出でき、それぞれにクラスラベルと位置情報が付与されます。Amazon SageMakerのオブジェクト検出アルゴリズムは、単一の深層ニューラルネットワークで物体の検出と分類を行い、シングルショットマルチボックス検出器（SSD）を基盤としています。
線形学習（Linear Learner）について
線形学習は、線形モデルを使って分類や回帰を行う教師あり学習アルゴリズムです。入力として数値ラベル付きの高次元ベクトルを受け取り、recordIO-wrapped protobuf形式とCSV形式に対応します。線形の重みを学習して二値分類・多クラス分類・回帰を解くアルゴリズムであり、画像のピクセルを直接扱って物体の位置を特定する機能はないため、コンピュータビジョンタスクには向きません。
主成分分析（PCA）について
主成分分析（PCA）は、教師なし学習の次元削減アルゴリズムです。データの分散が大きい方向へ軸を取り直し、少ない成分で元のデータを近似します。可視化や前処理には有用ですが、物体の識別や位置検出を行うアルゴリズムではありません。
図による解説



画像分類は画像全体に対してラベル（図では「猫」）を付けるだけで、画像内の物体がどこにあるかまでは示しません。一方、オブジェクト検出は画像内の複数の物体（図では「猫」と「犬」）をそれぞれ矩形のバウンディングボックスで囲み、位置と大きさまで特定します。SageMakerのオブジェクト検出は、単一の深層ニューラルネットワークで物体を検出・分類し、その場所を境界ボックスとして返します。選別ラインの素材識別では、素材の種類の判定に加えてロボットアームが把持する座標が必要なため、ラベルだけを返す画像分類では要件を満たせません。識別と位置特定を同時に行うオブジェクト検出を選ばないと、位置情報なしで素材を掴めません。
解くための考え方
画像内の素材を識別し、その位置まで返す必要があるため、ラベルだけを返す画像分類では足りません。線形学習は表形式データの分類・回帰向け、主成分分析（PCA）は次元削減向けであり、いずれも画像内の位置を特定する機能を持ちません。オブジェクト検出は、画像内の複数の物体を識別し、それぞれの位置をバウンディングボックスとして返すため、識別と把持座標の両方に応えます。

問題32
正解
ある企業が、翌月以降の売上を予測する時系列モデルを構築しました。
MLエンジニアは、このモデルがどれほど正確に売上を予測できるかを測るため、予測品質を評価するメトリクスを選定する必要があります。時系列予測モデルに適用されるメトリクスはどれですか。（2つ選択してください。）

対数損失（LogLoss）

説明
不正解 対数損失（LogLoss）は、各クラスに属する確率を出力する分類タスクで用いる評価指標で、正解ラベルに対して予測確率がどれだけ離れているかを対数で罰する形で測ります。正解クラスに低い確率を割り当てるほど値が大きくなり、二値分類や多クラス分類の確率較正の良し悪しを評価するのに適しています。翌月の売上のような連続値を当てる時系列予測は回帰タスクであり、クラスごとの確率という概念が存在しないためLogLossは適用できません。回帰の評価にはRMSEやwQLなどを使います。

選択は正解です
平均二乗誤差の平方根（RMSE）

説明
正解 RMSEは、予測値と実測値の差を二乗して平均し、その平方根を取る回帰タスクの代表的な評価指標で、時系列予測の品質評価にも用いられます。値が小さいほど予測が正確で、0であれば誤差のないモデルであることを示します。誤差を二乗するため、少数の大きな外れが値に強く反映される性質があり、売上予測のように予測のずれが欠品や過剰在庫といった大きな損失に直結する用途に適しています。単位が予測対象と同じになるため解釈も容易です。

推論レイテンシ（InferenceLatency）

説明
不正解 推論レイテンシは、推論リクエストを受け取ってからモデルが予測を返すまでにかかる時間を測る運用面の指標で、エンドポイントのインスタンスタイプやモデルサイズを見直す際の判断材料になります。測っているのは処理にかかる時間であり、予測値が実測値にどれだけ近いかという予測品質とは無関係です。レイテンシが小さくても予測が大きく外れていることはあり得るため、時系列予測モデルの品質評価には使えません。

再現率（Recall）

説明

前提知識
時系列予測について
時系列予測は、過去のデータのパターンから将来の値を予測する機械学習タスクです。たとえば、過去の売上実績から翌月の売上を予測します。時系列予測は連続値を予測する回帰タスクであるため、分類タスクの評価指標（適合率、再現率、精度など）は適用できません。回帰タスクの評価指標（RMSE、wQLなど）を使う必要があります。
RMSE（平均二乗誤差の平方根）について
RMSEは、回帰タスクの評価指標で、予測値と実測値の差の二乗平均の平方根を計算します。式は「√(Σ(予測値 - 実測値)² / n)」で表されます。RMSEは大きな誤差をより重視する性質があり、予測の誤差の大きさを一つの値で評価できます。時系列予測では、予測値と実測値の差をRMSEで評価することでモデルの性能を測定できます。単位は予測対象の値と同じになるため、解釈が容易です。
wQL（重み付き分位損失）について
wQL（重み付き分位損失）は、指定した分位数でのモデルの精度を測る指標で、時系列予測の予測区間の品質を評価します。時系列予測では、点予測（単一の値）だけでなく、将来の値が取りうる範囲（予測区間）も重要です。wQLは異なる分位点（例：P10、P50、P90）での予測精度を評価し、過小予測と過大予測のコストが異なる場合に重みを変えて評価できます。DeepARなどの時系列アルゴリズムで標準的に使われ、wQLが低いほど予測区間が正確であることを示します。
分類タスクの評価指標について
再現率（Recall）は、分類タスクの評価指標で、実際に正例だったデータのうち正しく正例と予測したデータの割合を示します。時系列予測は回帰タスクであるため、再現率は適用できません。同様に、対数損失（LogLoss）も主に確率を予測する分類タスクの評価指標で、時系列予測には適用できません。
推論レイテンシについて
推論レイテンシは、モデルが予測を生成するまでの時間を測定する指標で、モデルの実行速度を評価するために使われます。モデルの「品質」（予測精度）を評価する指標ではなく、実行効率を評価する指標です。時系列予測モデルの品質評価には、予測値と実測値の差を測る指標（RMSE、wQLなど）を使う必要があります。

解くための考え方
時系列予測は連続値を予測する回帰タスクであるため、分類タスクの評価指標（再現率、LogLossなど）は適用できません。RMSEは回帰タスクの評価指標で、予測値と実測値の差の二乗平均の平方根を計算します。大きな誤差を強く反映するため、売上予測のようにずれの大きさが損失に直結する用途で使えます。wQL（重み付き分位損失）は、時系列予測の予測区間の精度を評価する指標です。点予測だけでなく予測区間も対象になるため、wQLも回帰の品質評価に使えます。一方、推論レイテンシはモデルの実行効率を評価する指標で、品質評価には適用できません。RMSEとwQLが時系列予測の品質評価に使えます。
